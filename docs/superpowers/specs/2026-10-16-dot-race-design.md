# dot-race 설계 스펙

- 작성일: 2026-10-16
- 상태: 설계 승인됨, 구현 계획 작성 전
- 범위: v1 (한 시즌 플레이 가능한 공개 배포 버전)

## 1. 개요

도트(픽셀) 그래픽 웹 레이싱 매니지먼트 게임. 플레이어는 가상의 오픈휠 레이싱 팀 하나의 총 책임자(팀 감독)가 되어, 실제 F1 캘린더 순서를 따르는 24라운드 시즌에서 **전략으로** 종합우승을 노린다. 플레이어는 차를 직접 운전하지 않는다.

전략 요소: 타이어 선택, 피트인 시점, 차량 세팅(속도형 ↔ 코너링형), 레이스 중 페이스 지시, 경기 사이 차량 개발과 예산 운용.

### 1.1 확정된 결정

| 항목 | 결정 |
|---|---|
| 이름/브랜딩 | 팀·드라이버·서킷·대회 이름은 모두 가상. 실제 팀의 메인 컬러만 차용 |
| 레이스 화면 | 실시간 관전형 (도트 서킷 위 주행, 배속 조절, 실시간 지시) |
| v1 범위 | 퀄리파잉 + 레이스 + 경기 사이 차량 개발(예산/코스트캡) |
| 플랫폼 | PC 브라우저 우선. 모바일 최적화는 v1 범위 밖 |
| 레이스 길이 | 실제 랩 수의 약 28%로 고정 축소 (반올림, 최소 12랩) |
| 돌발 변수 | 날씨, 세이프티카/VSC, 기계 고장, 드라이버 실수. 신뢰성 개발 항목 포함 |
| 시즌 | v1은 한 시즌으로 종료 (시즌 종료 화면) |
| 기술 | React + Canvas 2D, Vite + TypeScript, Zustand, Vitest. 엔진은 UI와 분리된 순수 TS |
| 배포 | 정적 사이트 (Cloudflare Pages 또는 GitHub Pages). 서버 없음 |

### 1.2 v1 범위 밖

연습주행 세션, 스프린트 주말, 드라이버 트레이드/계약/연봉, 파워유닛 사용 개수 제한과 그리드 페널티, 타이어 세트 수량 할당, 레드 플래그, 트랙 리밋/언세이프 릴리스 페널티, 블루 플래그, 다음 시즌 이어하기, 레이스 도중 저장, 모바일 레이아웃, 멀티플레이어.

## 2. 브랜딩과 공개 배포 규칙

- "F1", "Formula 1", "Grand Prix", 실제 팀/드라이버/서킷 이름, 로고, 상표를 데이터와 UI 어디에도 쓰지 않는다.
- 도시/국가 이름은 개최지 표시에 사용할 수 있다 (예: "멜버른"). 서킷 이름과 대회 이름은 가상으로 짓는다 (예: "사우스레이크 서킷", "멜버른 그랑프리" 대신 "사우스레이크 컵").
- 팀 컬러는 실제 팀의 메인 컬러를 참고한 hex 값만 쓴다. 팀 이름은 컬러나 국가와 무관한 가상 이름.
- 공개 배포 전 체크리스트: `src/data/` 전체와 UI 문자열에서 실제 고유명사 검색 (10장).

## 3. 게임 흐름

### 3.1 시즌 구성

- 11개 팀, 팀당 드라이버 2명, 총 22대.
- 24라운드. 순서와 서킷 특성은 2026 F1 캘린더를 참고: 호주, 중국, 일본, 바레인, 사우디, 마이애미, 캐나다, 모나코, 바르셀로나, 오스트리아, 영국, 벨기에, 헝가리, 네덜란드, 이탈리아(고속), 마드리드, 아제르바이잔, 싱가포르, 오스틴, 멕시코, 브라질, 라스베이거스, 카타르, 아부다비.
- 각 서킷 레이아웃은 실제 서킷 모양을 단순화한 경로로 직접 작성한다.
- 포인트: 1~10위에 25-18-15-12-10-8-6-4-2-1. 패스티스트 랩 포인트 없음.
- 완주 인정(classified): 우승자 랩 수의 90% 이상 완료.
- 챔피언십: 드라이버 챔피언십, 컨스트럭터 챔피언십(팀 두 대 포인트 합산). 동점 시 우승 횟수, 그다음 2위 횟수 순으로 비교한다.

### 3.2 한 라운드의 흐름

1. **팩토리**: 개발 프로젝트 시작/확인, 예산 확인 (5장).
2. **주말 브리핑**: 서킷 특성(직선 비율, 타이어 마모도, 추월 난이도), 날씨 예보(확률), 이번 주말 드라이 컴파운드 3종.
3. **세팅**: 차 2대 각각의 밸런스 슬라이더(0 = 최대 속도형, 100 = 최대 코너링형).
4. **퀄리파잉**: 실시간 관전. 시작 시점에 세팅이 잠긴다(파르크 페르메).
5. **레이스**: 실시간 관전과 지시.
6. **결과**: 레이스 순위, 획득 포인트, 스폰서 보너스, 챔피언십 순위.
7. 다음 라운드로 진행. 24라운드 후 **시즌 종료 화면** (최종 순위, 플레이어 팀 성적 요약).

### 3.3 팀 선택과 난이도

- 시작 시 11개 팀 중 하나를 고른다. 팀마다 초기 차량 수치, 보유 자금, 드라이버 능력치가 다르다.
- 별도의 난이도 설정은 없다. 팀 선택 화면에 "예상 난이도"(쉬움/보통/어려움/도전)를 표시한다.

## 4. 시뮬레이션 엔진

### 4.1 시간 진행

- 고정 틱: 시뮬레이션 시간 0.25초.
- 배속: 일시정지 / 1x / 4x / 8x / 16x. 1x는 실시간. 기본값 4x.
- 렌더러는 마지막 두 스냅샷 사이를 보간해 그린다.
- 엔진은 브라우저 API(`window`, `document`, `Date.now`, `Math.random`)를 사용하지 않는다. 랜덤은 모두 시드 기반 RNG.
- 같은 시드 + 같은 초기 상태 + 같은 명령 시퀀스(틱 번호 포함) → 항상 같은 결과.

### 4.2 서킷 모델

서킷 데이터:
- `path`: 닫힌 경로의 점 목록 (렌더링 좌표, 480×270 기준).
- `segments`: 경로를 나눈 구간 목록. 각 구간 = `{ type: 'straight' | 'slowCorner' | 'fastCorner', length(m), baseTime(s) }`.
- `traits`: `straightRatio`(0~1), `tyreWear`(0.7~1.4 배율), `overtakeDifficulty`(0~1), `pitLossSeconds`(피트레인 손실), `realLaps`(실제 랩 수), `rainChance`(0~1).
- 피트레인 진입/출구 위치(경로 상의 거리).

### 4.3 랩타임 모델

각 차는 경로 위 누적 거리로 위치를 가진다. 매 틱마다 현재 구간의 목표 구간 시간을 계산하고, 그에 해당하는 속도로 전진한다.

```
구간 시간 = 기준 시간
          − 차량 성능 보정(구간 종류별)
          − 드라이버 페이스 보정
          + 타이어 손실
          + 연료 무게 손실
          + 더티 에어 손실
          + 페이스 모드 보정
          + 노면 상태 보정(젖음 vs 타이어)
          + 랜덤 노이즈(작게)
```

- **차량 성능 보정**: 직선 구간은 파워유닛 수치, 코너 구간은 에어로와 섀시 수치를 사용한다. 저속 코너는 섀시 비중, 고속 코너는 에어로 비중이 크다.
- **세팅 밸런스**: 슬라이더 값 `b`(0~100)는 직선 성능에 `(50 − b)` 비례 보너스, 코너 성능에 `(b − 50)` 비례 보너스를 준다. 각 서킷의 최적 밸런스는 `straightRatio`에서 유도한다. 최적에서 멀어질수록 종합 랩타임 손실이 커지도록 이차 패널티를 둔다. 최적값은 UI에 숫자로 표시하지 않는다.
- **연료**: 레이스 시작 시 최대 손실(초기값 1.5초/랩 상당)에서 결승선까지 선형으로 0이 된다. 연료 관리 지시는 없다.
- **더티 에어**: 앞차와 1.5초 이내일 때 코너 구간 시간 증가. 에어로 수치가 높으면 덜 받는다.

### 4.4 타이어

- 드라이 컴파운드: 소프트(S), 미디엄(M), 하드(H). 웻 컴파운드: 인터미디어(I), 웨트(W).
- 컴파운드별 초기 속도 차(초기값): S 0, M +0.6초/랩, H +1.1초/랩.
- 마모도 0~100%. 기본 랩당 마모(초기값, 축소 랩 수 기준): S 9%, M 6%, H 4%. 서킷 `tyreWear`, 드라이버 타이어 관리, 섀시 수치, 페이스 모드로 배율 조정.
- 마모에 따른 손실: 70%까지는 완만한 선형 증가, 70%를 넘으면 급격히 증가(클리프). 100%에 도달하면 펑크 위험이 생긴다.
- 노면 젖음도 `wetness`(0~1)와 타이어의 궁합:
  - 드라이 타이어: wetness 0~0.2에서 최적, 그 이상에서 급격히 느려지고 실수 확률 상승.
  - 인터미디어: 0.2~0.6에서 최적.
  - 웨트: 0.6 이상에서 최적.
- **규칙**: 레이스 중 한 번이라도 I/W를 사용하지 않았다면, 드라이 컴파운드 2종 이상을 사용해야 한다. 위반 시 레이스 결과에 실격 처리. AI와 플레이어 모두 동일하게 적용하며, UI는 위반 상태일 때 경고를 표시한다.
- 레이스 시작 타이어는 자유 선택 (퀄리파잉 타이어 강제 규칙 없음).

### 4.5 플레이어 지시

- **피트인**: 다음 피트 진입 시 들어온다. 교체할 컴파운드를 고른다. 이번 랩 진입 지점을 이미 지났으면 다음 랩에 적용된다.
- **페이스 모드**: 푸시 / 보통 / 세이브.
  - 푸시: 랩타임 감소, 타이어 마모 증가, 실수 확률과 고장 확률 증가.
  - 세이브: 랩타임 증가, 타이어 마모 감소.
- **팀 오더**: 두 차가 2초 이내로 붙어 있을 때 앞차에게 양보 지시. 다음 직선 구간에서 순서가 바뀐다.
- 지시는 언제든 가능하며, 일시정지 중에도 줄 수 있다.

### 4.6 피트스톱

- 손실 시간 = 서킷 `pitLossSeconds` + 정지 시간.
- 정지 시간: 기본 2.2~3.0초 랜덤. 5% 확률로 느린 정지(+2~6초).
- SC 중에는 다른 차들이 느리게 달리므로 상대적 손실이 자연히 줄어든다. VSC 중에는 피트 손실에 0.6배를 적용한다.

### 4.7 추월

- 뒤차가 앞차와 1.0초 이내이고 직선 구간에 있으면 추월 시도.
- 1.0초 이내에서는 "오버테이크 모드"로 직선 구간 시간이 약간 감소한다.
- 성공 확률 = f(뒤차와 앞차의 순간 페이스 차이, 뒤차 추월 능력 − 앞차 방어 능력, 서킷 `overtakeDifficulty`).
- 실패하면 뒤차는 다음 직선까지 앞차 뒤에 묶인다(속도를 앞차에 맞춘다).
- 추월 시도에는 아주 작은 접촉 확률이 있다(실수/사고로 처리).

### 4.8 돌발 변수

**날씨**
- 레이스 전에 날씨 타임라인을 시드로 생성한다(랩별 강수량). 브리핑에는 확률 예보만 보여준다 (예: "20랩 이후 비 40%").
- 강수 중에는 `wetness`가 증가하고, 비가 그치면 감소한다(드라이 라인 형성).
- 퀄리파잉에도 같은 날씨 모델을 적용한다.

**드라이버 실수** (틱 단위가 아니라 구간 진입마다 판정)
- 확률 증가 요인: 낮은 안정성, wetness와 타이어 불일치, 푸시 모드, 높은 타이어 마모, 낮은 빗길 실력.
- 결과(확률 순): 소폭 시간 손실(0.5~2초) > 코스이탈(3~10초) > 크래시(리타이어).

**기계 고장**
- 랩마다 고장 판정. 확률은 신뢰성 수치와 페이스 모드로 결정한다.
- 결과: 대부분 리타이어. 일부는 출력 저하(남은 레이스 동안 직선 성능 감소).
- 목표 빈도: 시즌 평균 레이스당 리타이어 1~2대 (실수 + 고장 합산).

**세이프티카 / VSC**
- 크래시 또는 코스 위 정지 차량이 생기면 발동한다. 크래시는 70% SC / 30% VSC, 고장 정지는 30% SC / 70% VSC.
- SC: 추월 금지, 모든 차가 감속하며 대열이 압축된다. 2~4랩 후 해제되고, 해제 직후 재시작한다.
- VSC: 추월 금지, 모든 차가 정상 구간 시간의 약 140%로 달린다. 1~2랩 후 해제.
- 목표 빈도: 레이스의 약 50%에서 SC 또는 VSC 1회 이상.

### 4.9 레이스 시작

- 퀄리파잉 순위대로 그리드에 정렬한다.
- 스타트 반응은 드라이버 안정성 기반의 랜덤으로 결정한다. 첫 구간에서 순위 변동이 일어날 수 있다.

### 4.10 퀄리파잉

- 22대 기준: Q1 종료 시 하위 6명 탈락(17~22위), Q2 종료 시 하위 6명 탈락(11~16위), Q3에서 상위 10명 순위 결정.
- 세션 길이(시뮬레이션 시간): Q1 9분, Q2 7.5분, Q3 6분 (실제 길이의 50%).
- 각 차는 피트 대기 → 아웃랩 → 어택 랩 → (추가 어택 또는 인랩) 흐름으로 움직인다.
- 플레이어 지시: 출격 시점, 사용 컴파운드, 어택 랩 횟수(1 또는 2).
- 트랙 에볼루션: 세션이 진행될수록 기준 시간이 조금씩 줄어든다.
- 트래픽: 어택 랩 중 앞차와 가까우면 더티 에어 손실을 받는다.
- 세션 종료 신호 전에 어택 랩을 시작한 차는 그 랩을 완료할 수 있다.
- 타이어 세트 수량 제한 없음.

### 4.11 AI 전략가

- 레이스 시작 전, 서킷 마모도와 컴파운드 특성으로 예상 총 시간을 비교해 1스톱 또는 2스톱 계획을 고른다. 팀 성향과 랜덤으로 다양성을 준다.
- 반응 규칙:
  - SC/VSC 발동 시: 남은 계획상 피트가 가까우면 즉시 피트.
  - wetness가 타이어 범위를 벗어나면: 다음 랩에 맞는 타이어로 교체.
  - 마모가 클리프에 도달하면: 계획보다 일찍 피트.
- 2종 컴파운드 규칙을 지킨다.
- AI는 플레이어와 같은 명령 인터페이스로 엔진에 지시를 보낸다.

## 5. 차량 개발과 경제

### 5.1 차량 수치 (각 0~100)

| 항목 | 영향 |
|---|---|
| 에어로 | 코너 성능(특히 고속), 더티 에어 내성 |
| 섀시 | 코너 성능(특히 저속), 타이어 마모 감소 |
| 파워유닛 | 직선 성능 |
| 신뢰성 | 고장 확률 감소, 푸시 모드의 고장 위험 감소 |

### 5.2 드라이버 능력치 (각 0~100)

페이스, 안정성, 타이어 관리, 빗길 실력, 추월, 방어. v1에서는 시즌 중 변하지 않는다.

### 5.3 개발 프로젝트

- 팩토리 화면에서 항목 하나와 규모를 골라 시작한다. 동시 진행 최대 2개.
- 규모별 초기값:

| 규모 | 기본 비용 | 소요 | 상승폭 |
|---|---|---|---|
| 소 | 4M | 1라운드 | +1~3 |
| 중 | 9M | 2라운드 | +3~6 |
| 대 | 16M | 3라운드 | +5~10 |

- 실제 비용 = 기본 비용 × (1 + 현재 수치 / 100). 수치가 높을수록 비싸진다(수확 체감).
- 상승폭은 범위 안에서 시드 랜덤. 완료 시 결과를 알려준다.
- 프로젝트 비용은 시작할 때 전액 지출된다. 취소는 불가.
- 수치 상한은 100.

### 5.4 예산과 코스트캡

- 시즌 코스트캡(초기값): 140M. 시즌 동안의 총 지출(개발 + 수리)이 상한을 넘을 수 없다. 넘게 되는 프로젝트는 UI에서 시작 버튼이 비활성화된다.
- 팀 보유 자금(초기값): 팀별 70M~150M. 하위 팀은 자금이 부족해서 상한까지 쓰지 못한다.
- 스폰서 보너스: 라운드마다 팀이 획득한 포인트 × 0.3M을 지급한다. 보유 자금이 늘어날 뿐, 코스트캡 한도가 늘어나지는 않는다.
- 크래시 수리비: 2~5M. 보유 자금에서 차감되며 코스트캡 지출에 포함된다. 수리비 때문에 자금이 음수가 되면 자금은 0으로 두고, 부족분은 다음 스폰서 보너스에서 차감한다.

### 5.5 풍동 제한 (에어로 개발 보정)

- 현재 컨스트럭터 순위에 따라 에어로 프로젝트 비용에 배율을 적용한다. 1위 ×1.00에서 11위 ×0.75까지 선형.
- 1라운드 전에는 전 시즌 순위 대신 팀의 초기 서열을 사용한다.

### 5.6 AI 팀 개발

- AI 팀도 같은 규칙(비용, 코스트캡, 동시 2개)으로 라운드마다 프로젝트를 고른다.
- 팀 성향 가중치(예: 에어로 중시, 신뢰성 중시, 균형)와 현재 약점을 반영한다.

### 6.2 엔진 인터페이스

```ts
interface SessionSim {
  step(): void;                    // 0.25초 진행
  enqueue(cmd: Command): void;     // 플레이어/AI 지시
  snapshot(): SessionSnapshot;     // 렌더/UI용 읽기 전용 상태
  isFinished(): boolean;
  result(): SessionResult;
}
```

- 레이스와 퀄리파잉 모두 `SessionSim`을 구현한다.
- `Command`는 `{ tick, carId, kind: 'pit' | 'paceMode' | 'teamOrder' | 'qualiRun', ... }` 형태.
- 시즌 단위 로직은 `step` 루프와 별개인 순수 함수로 구현한다: `applyRaceResult(season, result)`, `startProject(season, teamId, area, size)`, `advanceRound(season)`.

### 6.3 데이터 흐름

- 세션 루프(`store/`): `requestAnimationFrame`마다 배속에 맞는 틱 수만큼 `step()`을 호출한다. 1x 기준 초당 4틱.
- Canvas는 매 프레임 스냅샷을 읽어 그린다.
- React 패널(타이밍 타워, 차량 패널, 이벤트 로그)은 초당 4회 갱신되는 스냅샷 사본을 구독한다.
- UI의 지시는 `enqueue`로만 엔진에 전달된다.

### 6.4 도트 그래픽

- 내부 해상도 480×270. `image-rendering: pixelated`로 정수 배율 확대한다.
- 서킷은 오프스크린 캔버스에 한 번 그려 캐시하고, 매 프레임 차량만 그린다.
- 차량 스프라이트: 코드에 정의한 작은 도트 패턴(약 5×3픽셀) 하나에 팀 컬러를 입힌다. 외부 이미지 파일 없이 시작한다.
- 깃발 상태(SC/VSC)와 비는 캔버스 위 오버레이로 표현한다.
- 렌더러는 `render/` 안에 인터페이스로 감싸서, 필요하면 나중에 PixiJS로 교체할 수 있게 한다.

## 7. 저장

- `localStorage`에 JSON으로 저장한다. 키: `dot-race:save`, 백업 키: `dot-race:save:backup`.
- 저장 형식에 `schemaVersion`(v1 = 1)을 포함한다.
- 저장 시점: 각 라운드 결과 확정 직후, 팩토리 화면에서 변경할 때. 저장 직전에 기존 저장본을 백업 키로 복사한다.
- 레이스/퀄리파잉 도중에는 저장하지 않는다. 도중에 이탈하면 해당 세션을 처음부터 다시 진행한다.
- 저장 데이터에는 시즌 시드를 포함한다. 각 세션 시드는 시즌 시드와 라운드 번호로 유도한다.

## 8. 오류 처리

- 불러오기 실패(파싱 실패, 버전 불일치, 필수 필드 누락): 백업 슬롯을 시도하고, 그것도 실패하면 "저장 데이터를 불러올 수 없음" 안내와 함께 새 게임을 제안한다. 손상된 데이터로 진행하지 않는다.
- `localStorage` 접근 실패(시크릿 모드, 용량 초과 등): "저장 없이 플레이 중" 배너를 표시하고 게임은 계속한다.
- 엔진 불변식 위반(음수 마모, NaN 위치, 존재하지 않는 차 ID 명령 등): 개발 빌드에서는 즉시 예외를 던진다. 프로덕션 빌드에서는 해당 명령을 무시하고 콘솔에 기록한다.

## 9. 테스트와 밸런싱

### 9.1 테스트 (Vitest)

엔진 단위 테스트:
- RNG 재현성. 같은 시드 + 같은 명령이면 레이스 결과 전체가 동일함.
- 랩타임: 성능/세팅/타이어/연료 각 요소가 올바른 방향으로 작용함.
- 타이어 마모 곡선과 클리프. 젖음도와 타이어 궁합.
- 2종 컴파운드 규칙 판정. 웻 타이어를 사용하면 면제됨.
- 포인트 배분, 완주 인정 90% 규칙, 챔피언십 동점 처리.
- 퀄리파잉 탈락 인원(6/6)과 그리드 순서.
- SC/VSC 중 추월 금지.
- 개발 비용 공식, 코스트캡 차단, 풍동 제한 배율, 수리비 처리.
- 파르크 페르메: 퀄리파잉 시작 후 세팅 변경 거부.
- 저장/불러오기 왕복, 버전 불일치 처리.

UI 테스트는 최소화한다. 핵심 흐름 1개만 검증한다: 팀 선택 → 1라운드 완주(최고 배속) → 저장 → 새로고침 → 불러오기.

### 9.2 밸런싱 도구

`scripts/balance.ts`: 화면 없이 엔진만으로 시즌 N회(기본 200회)를 시뮬레이션해 통계를 출력한다. 플레이어 팀도 AI가 운영한다.

확인 목표:
- 시즌 우승 팀 분포: 초기 1위 팀의 우승 확률이 60%를 넘지 않음.
- 하위권(초기 서열 8~11위) 팀의 시즌 평균 순위가 개발로 상승 가능함.
- 서킷에 따라 1스톱과 2스톱이 각각 최선인 경우가 모두 존재함.
- 레이스당 평균 리타이어 1~2대, SC/VSC 발생 레이스 비율 40~60%.

모든 수치는 `engine/config.ts` 한 곳에서 관리한다.

## 11. 개발 순서 (구현 계획에서 세분화)

1. 엔진 골격: RNG, config, 타입, 서킷 1개, 단순 랩타임으로 22대 주행.
2. 렌더러 + 세션 화면 최소판: 맵 위에서 차가 달리고 타이밍 타워가 갱신됨.
3. 타이어/피트/페이스 모드/추월. 플레이어 지시 연결.
4. 퀄리파잉, 그리드, 레이스 규칙, 포인트.
5. 시즌 루프: 허브, 결과, 챔피언십, 저장.
6. 팩토리: 개발 프로젝트, 예산, 코스트캡, AI 개발.
7. 돌발 변수: 날씨, 실수, 고장, SC/VSC.
8. AI 전략가 고도화, 밸런싱 스크립트, 수치 조정.
9. 서킷 3개로 전체 시즌 루프 완성 후, 나머지 21개 서킷 데이터 추가.
10. 배포 점검과 공개.
